# Recovery and validation after a failed run

This procedure implements Matt's 30 October operating direction. It changes how MyGame work is recovered and delivered, while retaining existing source ownership, validation gates and art approval.

## What the incidents establish

[The first diagnostic](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6503169778) preserved the Crossroads error but failed to archive object-array `ground0`. [Assumed-route replay](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6503684005) refused IDs 16–23 instead of the actual world's 20–23: internal consistency did not establish reproduction. [Fixture allocation errors](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6504471913) and a later [wall-cap timeout](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6504795857) were separate failures. Completed methods keep their individual attribution.

[R4](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6505567471) eventually produced a complete seven-file diagnostic of a still-failed world. [The recovery request](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6519694007) then required retrievable input and replay bytes. Missing paths in one reviewer's mount prove an access problem, not deletion, its cause, or absence elsewhere. [The 30 October brief](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6520001613) distinguishes about 49.5 minutes of selected recorded runtime from roughly 20 hours elapsed. That subset does not measure all work or explain every gap; review, allocation and access waits require their own accounting.

## Preserve the first failure, then reproduce it

Publish source in Git and one portable evidence bundle for every expensive run, including its FIRST failure. Include actual required inputs/state and support bounds, source/seed, exact command, sanitised task environment/version pins, raw logs/exits, failure core, results and any produced images. Exclude credentials and player data. Explicitly record absent outputs. Write failure core and trials before optional serialization can fail. Hashes identify bytes; hashes and scratch paths cannot replace them.

Give the bundle a retrievable location and suitable retention. Before HANDOFF is complete, a second workspace or reviewer must retrieve and verify its bytes. Record who retrieved what and when. If retrieval fails, publish the precise blocker and next action; do not declare the evidence delivered.

Inside the reviewed allocation, test cheap prerequisites first: actual renderer/display authority, supported ABI and imports, serializer field names/dtypes/shapes, and available input/support coverage. [The #390 reviews](https://github.com/rempemat-eng/appify/pull/390#pullrequestreview-5702401317) also show why authored process controls and source clearance are not executed ownership or cleanup proof.

Before geometry changes, reproduce the unchanged receiving consumer on exact retained inputs, including actual routes/rivers/streets/spaces. Y35's 125 events/19 records/error20–23 and after-state target apply to original R4 input, currently unretrievable. The [source-only R6 replacement brief](https://github.com/rempemat-eng/appify/issues/149#issuecomment-6520206202) prepares a new capture: later allocated execution must persist its own observed baseline, compare the known historical summary, and never claim old-array parity. Uncaptured active dependencies/support must refuse honestly; bounded pointwise full-array scans are allowed when target equivalence is proved. Never invent missing inputs or call a simplified fixture actual terrain.

Then make the measured correction and test the full receiving consumer. Street reuse and frontage must share actual snapped geometry; authored yard/layout contracts must protect working ground. Exercise all five Neon districts, not inventory or one frontage alone. Preserve placement physics, fixed footprints, IDs and approval boundaries. Label the crop's source and actual/derived status; a diagnostic PNG does not approve the continent.

## One bounded recovery through the next artifact

One reviewed allocation should cover necessary setup, targeted RED/fix/GREEN, a labelled crop, publication and final collection within its named branch, inputs, resources and stop bounds. Budget setup and collection, not only child CPU. Continue already-approved substeps without another decision between each one. Unexpected new defects, scope/resource/security changes or an exhausted allocation return to the lead; no automatic retry or silent budget increase. Reuse unchanged completed suites. Freeze the final exact source before the canonical gate.

If a workspace is missing, perform one bounded search of known owners, published source and evidence locations. Report which bytes remain retrievable or inaccessible. Within the allocation, create a clearly labelled checkout from the exact remote source when needed. Record its new identity and baseline; never claim equality to an unavailable old index or restore/reset player data.

If no copy of required actual inputs is retrievable, the lead explicitly decides whether to make a replacement capture from pinned source/seed. Preserve the old result as historical/unretrievable and distinguish the replacement. Do not repeat indefinite old-index guards or present reconstructed assumptions as recovered evidence.

## Ownership, review and handoff

Every review/allocation wait names an owner, next executable command and next visible artifact. Manual execution reservations end on completion, pause or turn handoff; explicitly transfer any live bounded collector and its stop bound. A reservation for work that never started cannot indefinitely block the existing lead scheduler. This does not release worker production claims or permit competing expensive jobs.

Use proportional coordination reads: retain the last verified cursor, read new/edited #149 comments through all pages, and refresh the canonical board, current head and relevant active claims. Broader history/file inventories are for changed or ambiguous ownership, not unchanged hourly polls. Keep health updates concise, linking retained proof.

The lead finishes ready source reviews before stocking more report tasks, delegates by disjoint files and real dependencies, and uses the same board and daily summary. Progress means a source, test, render or merge result; a heartbeat is availability information. No duplicate supervisors/writers, force-pushes, Player edits, resets or protection changes.

Use this handoff:

```text
Owner / claim / branch:
Exact source head / tree / inputs / seed:
Portable bundle / retention / second-reader byte verification:
Recovery stage / old evidence status / known versus unknown:
Approved command / versions / setup-through-collection bounds:
Actual RED/GREEN / exits / completed methods / labelled image:
Reservation ended or live collector transferred to:
Next owner / executable command / visible artifact:
```

Final exact-source verify with zero lint warnings, ordinary art reproduction, relevant kit/Godot and applicable hosted checks remain required. Partial, skipped or absent results are not passes. Matt's explicit PR-specific art/map/kit/cast approval remains unchanged; this procedure adds no game rules or art direction.
