## PROPOSE order after consolidation

This is an order for Claude to choose, not a new implementation queue or file grant.

1. **Glint transaction bridge, if a receipt boundary is needed for the next slice action.** It can reuse an already playable transaction and existing values. First settle old-save reconciliation and the save writer; keep the current working purse/service path until the bridge is verified.
2. **One-folk progression integration after its level/effect decision.** Establish the shared projection and one end-to-end approved node before exposing all fourteen trees. A preview is preparation, not the resulting playable mechanic.
3. **One weapon transition after progression/payment ownership and the production-data contract.** Read-only stage inspection can precede this, but live transformation also belongs to the combat/animation owner.
4. **Clock presentation last, after the day/night decision.** It is not needed to make the existing first-night raid work and must not change that raid's timing or the economy.

If those decisions are not yet made, retain the models and finish already assigned slice interactions rather than inventing integration rules. Any implementation needs a new scoped lead assignment, disjoint ownership and separately allocated exact-source validation.
