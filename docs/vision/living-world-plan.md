# The living world: merged plan and schedule

Approved by Matt on 17 Oct 2026 (19:16): "try to implement most of the ideas … schedule everything in a way that makes sense". This merges his 11:54 brief (currency and decay, menus, biomes, decorating, interiors, NPCs, visual depth) with Codex's proposals (seasons, weather and time as a scenery layer; a world with a memory; the destination map). `coherence-plan.md` still holds the art rules and the Codex lanes; this file holds the order of the new work.

## Rules that hold for every phase

- **Screen time first.** The game rewards time away from the phone. Nothing asks the player to come back, watch an animation or keep a streak alive to avoid loss.
- **The currency (GRASS) is never lost, stolen or expired.** It only goes down when the player spends it.
- **Decay is visual, capped and reversible.** It never deletes anything the player owns, and it only reverses through a repair the player chooses.
- **Atmosphere is presentation.** Season, weather and time of day change props, light and activities, never rewards, mood, timers or progress.
- **Lasting history is saved and never decays.** A built shelter, a chosen library edition or a befriended resident stays. A long absence gives one readable welcome, not a backlog.
- **Same art rules everywhere** (`coherence-plan.md`, `art-pipeline.md`): the shared grid, the steep top-down view for buildings, material detail, silhouette shadows, night light. New biomes are drawn with the same toolkit from the first prop.
- **Phones first.** Every new layer has an image-memory cost in `check:images`; reduced motion shows a still; touch targets stay at least 44 px.

## Who does what

Claude draws, lays out and wires the screens. Codex builds the rules, stores, save migrations and tests underneath, each as a small PR (lanes in `coherence-plan.md`). A phase starts when its Codex engine exists or alongside it; Claude never builds UI against an API that is not on main.

## How Codex keeps ideating

Codex reads this file and `coherence-plan.md` on every run. When its queue is empty it play-tests the latest main and writes ideas in `docs/codex/ideas/<topic>.md`, each grounded in what is on main now (the steep top-down buildings, the detail toolkit, night light, this schedule) and in the rules above: problem, proposal, which phase it extends, the art it needs, risks, effort and open questions for Matt. Claude reviews new idea files on each pass, folds the good ones into a phase here and answers under Feedback in `coherence-plan.md`. Nothing in an idea file is built until it appears in this schedule.
