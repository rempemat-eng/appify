#! legacy-save: first_night.save.json
# Intentionally import the old folder on the first normal boot; restarts load MyGame.
# The first night lost, then held (Matt, 13 Nov: "Shard dims until held"; core/raids.gd, world/raid_night.gd),
# played with real input from the save first_night.txt starts from. The player takes both hurdles off the
# pads and stands on the garden walk while the shardstruck walk down an open road and break the shard
# lantern. From that moment the lantern is dark and the square looks worse (the two repairs): on the square,
# after a quit and a load, after walking out and back in, on the prepare screen and through the next night,
# and nothing else is taken (the Glint, the restores and the quests are as they were). The second night is
# put back as Hale set it and held from the square; the lantern is lit again and stays lit, the repairs are
# gone, and Hale says it was the one night. The torn roof is done first (as first_night.txt does it last),
# so the tracker is the first night's own lead and its dark wording can be read off the screen.
# No pilot plays the loss: it is `button`, `wait` and `waitfor` only. The second night uses `defend` as
# first_night.txt does, with the state checked before it at the moments the beats depend on. Losing by
# going down is not played here (test/test_raids.gd, test_going_down_in_a_night_costs_no_glint, plays it
# through the game scene): the `down` pilot stands by the nearest raider, and a raider behind a hurdle does
# not turn on the player, so which way the night is lost would depend on the run.
# Commands: tools/play_driver.gd.
